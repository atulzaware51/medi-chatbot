# Medibot Security Review

Review date: 2026-11-06

## Scope and limits

Reviewed current authentication, chat ownership, retention, rate limiting,
admin access controls, database configuration, migrations, deployment
configuration, and related tests. The local `.env`, private documents, and
database contents were not opened. No live deployment, PostgreSQL test,
external penetration test, or current Python dependency advisory scan was
performed. This source review is not a security certification.

## Implemented protections

- Passwords are hashed with Argon2id.
- Session and CSRF tokens are generated opaquely; only their hashes are stored
  in the database. Sessions expire after seven days and are revocable.
- Session cookies are HttpOnly and SameSite=Strict. State-changing
  authenticated requests validate a session-bound CSRF token.
- Conversation IDs are generated by the server, and each read/write/delete
  operation filters by the authenticated owner.
- Conversation and account deletion, 30-day default inactivity expiry
  (configurable from 1–365 days), and a 100-message cap are implemented.
- Database-backed rate limits cover registration/login, chat, and admin login.
- Remote admin access is disabled by default; the example configuration
  contains no preset admin password.
- Regression tests cover authentication, expiry, CSRF, ownership isolation,
  deletion, rate limits, and database migrations.

## Remaining risks and required actions

### HIGH: Deployment and recovery are unverified

The local Docker CLI could not reach its Linux engine. No target-host
PostgreSQL migration/concurrency test, backup, or restore exercise has been
completed. The Render Blueprint is configuration, not proof of deployment or
durable recovery.

**Required before public use:** build and run the image; validate migrations
and rate limits on PostgreSQL; verify disk/database persistence through
redeploy; perform and document a restore test.

### HIGH: No email verification or password recovery

Public registration accepts an email without confirming its ownership, and
there is no password reset or support process. The registration/login
throttle is not a substitute for account-abuse or recovery controls.

**Required before public signup:** decide the account recovery/support policy
and implement suitable abuse protections without exposing account existence
or sending credentials insecurely.

### HIGH: Not clinically validated; no real patient data

Emergency phrase matching and diagnosis/medication refusal logic are limited
and cannot guarantee safe medical behavior. No qualified clinical, legal, or
privacy review has occurred.

**Required:** keep the product clearly educational, do not accept real patient
information, and obtain appropriate expert review before any clinical use.

### MEDIUM: Remote admin requires additional controls

Remote admin is disabled in the Render template. Application-level login
throttling does not protect an internet-exposed admin interface against all
abuse.

**Required:** keep remote admin disabled unless a separate trusted
identity-aware/network access control is configured and reviewed. Set unique
secrets in host settings; never use `.env.example` values.

### MEDIUM: Frontend development dependency advisories remain

The production Python lock passed `pip-audit` after the seven advisories in
`pypdf==6.21.2` were fixed by updating the lock to `pypdf==6.21.4`.
`npm audit --omit=dev` reports zero production advisories. The earlier full
npm audit currently reports four moderate `minimatch` advisories through the
ESLint 10 development dependency chain. Non-breaking `npm audit fix` did not
resolve them; npm proposes an ESLint 9 downgrade that npm marks unsupported/
deprecated, so it was not adopted.

**Required:** review and refresh the full npm audit before release. CI now
audits the production Python and npm dependency sets on pushes and pull
requests. Keep the supported ESLint 10 line and monitor for an upstream fix;
do not adopt the deprecated downgrade.

### MEDIUM: Operational/privacy controls need production evidence

Retention cleanup, backup policy, database outage behavior, and production
logging/monitoring have not been verified on Render. Inactive conversation
deletion is not a substitute for a documented privacy policy or regulatory
review.

**Required:** test cleanup and outage behavior, define retention and incident
processes, and ensure logs/analytics do not capture questions, credentials, or
other sensitive content.

## Overall assessment

The source now has account-scoped conversation access and several important
security controls, but the service is **not ready for public or real-health-
data use**. Hosting, recovery, account support/abuse controls, dependency
scanning, and qualified clinical/legal/privacy review remain open. No claim
of security certification, compliance, or medical safety is made.
